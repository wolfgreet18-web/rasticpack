# رستیک پک — نسخه اندروید (مرحله ۲: دیتابیس)

این پوشه یک پروژه‌ی Android (Kotlin + Jetpack Compose) است. تا این مرحله سه چیز ساخته شده:

1. اسکلت پایه‌ی اپ + رنگ/لوگوی برند + پایپلاین ساخت خودکار APK (مرحله‌ی «پروژه پایه»).
2. **موتور محاسبه** (`engine/CalculatorEngine.kt`) — معادل دقیق بخش `CORE ENGINE` در
   `4.html`: `isGrainCorrect`، `calcLayout`، `matchSheets`، به‌همراه یک صفحه‌ی تست ساده
   (`ui/engine/EngineTestScreen.kt`) که از صفحه‌ی خانه با دکمه‌ی «🧮 تست موتور محاسبه»
   باز می‌شود.
3. **دیتابیس (Room)** — معادل بخش `STATE`/`STORAGE` در نسخه‌ی وب (که آنجا با IndexedDB +
   window.storage پیاده شده بود، به‌خاطر سقف ۵ مگابایتی مرورگر). این محدودیت در اندروید
   اصلاً وجود ندارد، پس همه چیز در یک دیتابیس SQLite واحد (از طریق Room) نگه داشته می‌شود:
   - جدول‌ها: `InventorySheetEntity` (موجودی ورق)، `CustomerEntity` (مشتری‌ها)،
     `InvoiceEntity` + `InvoiceItemEntity` (فاکتور و آیتم‌هایش، با رابطه‌ی
     `InvoiceWithItems`)، `VanDriverEntity` (رانندگان وانت)، `ProductionQueueItemEntity`
     (صف تولید)، و `AppSettingsEntity` (یک ردیف تک برای قیمت ورق‌ها، وزن ورق، قیمت
     ضایعات، متن پیامک، سربرگ فاکتور، و تنظیمات نمایشی).
   - **نکته:** بر خلاف وب، اینجا دیگر نیازی به شمارنده‌های `nextId`/`nextCustId`/... نیست
     چون Room خودش با `autoGenerate` شناسه‌ی یکتا می‌سازد.
   - یک صفحه‌ی تست (`ui/database/DatabaseTestScreen.kt`) که از صفحه‌ی خانه با دکمه‌ی
     «🗄️ تست دیتابیس (۱۰٬۰۰۰ فاکتور)» باز می‌شود: دکمه‌ی «🚀 تولید ۱۰٬۰۰۰ فاکتور نمونه»
     ده‌هزار فاکتور واقعی در دیتابیس گوشی می‌سازد و مدت‌زمان اجرا را نشان می‌دهد؛ لیست
     فاکتورها هم دقیقاً مثل نسخه‌ی وب صفحه‌بندی‌شده (۵۰ تایی، با دکمه‌ی «نمایش ۵۰ فاکتور
     بعدی») نمایش داده می‌شود تا مطمئن شویم اسکرول با هزاران رکورد هم نرم می‌ماند.

هدف این مرحله این است که مطمئن شویم فرمول‌های محاسبه‌ی چیدمان/پرت روی ورق، عیناً همان
عددهایی را می‌دهند که نسخه‌ی وب می‌دهد، و ساختار داده هم برای حجم واقعی (هزاران فاکتور/
مشتری) بدون کندی کار می‌کند — قبل از اینکه UI نهایی هر تب ساخته شود.

## چطور این مرحله را روی گوشی تست کنم؟

1. اپ را باز کنید؛ در صفحه‌ی خانه دو دکمه‌ی تست می‌بینید: «🧮 تست موتور محاسبه» (مرحله ۱)
   و «🗄️ تست دیتابیس (۱۰٬۰۰۰ فاکتور)» (همین مرحله).
2. روی «🗄️ تست دیتابیس» بزنید.
3. روی «🚀 تولید ۱۰٬۰۰۰ فاکتور نمونه» بزنید و صبر کنید تا تمام شود (چند ثانیه طول می‌کشد؛
   مدت دقیق اجرا روی صفحه نشان داده می‌شود).
4. لیست پایین صفحه باید ۵۰ فاکتور اول را نشان دهد. با اسکرول تا پایین لیست، دکمه‌ی
   «نمایش ۵۰ فاکتور بعدی» را بزنید — این کار را چند بار تکرار کنید و مطمئن شوید اسکرول
   کند/هنگ نمی‌شود.
5. برای پاک کردن داده‌ی تستی، «🗑 پاک کردن همه فاکتورها» را بزنید.
6. اپ را کامل ببندید و دوباره باز کنید؛ فاکتورهایی که ساخته‌اید باید همچنان روی گوشی
   مانده باشند (چون در دیتابیس واقعی ذخیره می‌شوند، نه فقط در حافظه‌ی موقت).

## چطور APK را بسازم و روی گوشی نصب کنم؟ (بدون کامپیوتر یا Android Studio)

1. یک مخزن (repository) تازه در گیت‌هاب بسازید و تمام فایل‌های این پوشه را در آن آپلود کنید
   (می‌توانید از طریق سایت گیت‌هاب فایل‌ها را درگ-اند-دراپ کنید، یا این پوشه را زیپ کرده و
   از گزینه‌ی «Upload files» استفاده کنید — نکته: پوشه‌ی `.github` هم باید حتماً آپلود شود،
   چون فایل ساخت خودکار همان‌جاست).
2. بعد از آپلود، به تب **Actions** مخزن بروید. یک اجرا (run) به اسم «ساخت APK» خودش شروع
   می‌شود (چون فایل build.yml تنظیم شده که با هر push اجرا شود). اگر شروع نشد، دستی روی
   دکمه‌ی **Run workflow** بزنید.
3. صبر کنید تا اجرا سبز (✅) شود — حدود ۲ تا ۴ دقیقه طول می‌کشد.
4. روی همان اجرا کلیک کنید؛ در پایین صفحه بخش **Artifacts** یک فایل به اسم
   `rasticpack-debug-apk` می‌بینید. آن را دانلود کنید — یک فایل zip است که داخلش
   فایل APK قرار دارد.
5. فایل APK را به گوشی اندرویدی خودتان منتقل کنید (مثلاً از طریق تلگرام به خودتان، یا
   دانلود مستقیم از گوشی روی همان صفحه‌ی گیت‌هاب) و نصبش کنید. اندروید ممکن است هشدار
   بدهد «از منبع ناشناس» — این طبیعی است، چون اپ از گوگل‌پلی نیامده؛ اجازه‌ی نصب را بدهید.

## چیزهایی که در این مرحله *نیستند* (در مراحل بعد اضافه می‌شوند)

- تب‌های واقعی با UI کامل: محاسبه کارتن (قیمت‌گذاری)، موجودی ورق، مشتری‌ها، فاکتورها،
  مراحل تولید، آمار سود، تنظیمات/بکاپ
- Repository/ViewModel که دیتابیس را به این تب‌ها وصل کند (فعلاً فقط صفحه‌ی تست مستقیم
  از AppDatabase می‌خواند/می‌نویسد — ساختار Repository معمولاً وقتی UI تب‌ها ساخته شود
  اضافه می‌شود تا از قبل بیش از حد انتزاعی نشویم)
- پیامک/اشتراک‌گذاری/PDF فاکتور، ابزار رسم بلانک کارتن (SVG معادل در Compose)
- فونت فارسی وزیرمتن (فعلاً فونت پیش‌فرض سیستم استفاده می‌شود — فارسی را درست نشان
  می‌دهد، فقط ظاهرش با نسخه‌ی وب یکی نیست)

## ساختار پوشه‌ها

```
RasticPack/
├── app/
│   ├── build.gradle.kts                 ← کتابخونه‌ها و تنظیمات ماژول اپ (شامل Room/KSP)
│   └── src/main/
│       ├── AndroidManifest.xml
│       ├── java/com/rasticpack/app/
│       │   ├── MainActivity.kt          ← نقطه ورود + صفحه خوش‌آمد
│       │   ├── engine/                  ← موتور محاسبه (مرحله ۱)
│       │   ├── data/
│       │   │   ├── AppDatabase.kt       ← تعریف دیتابیس Room و همه‌ی DAO ها
│       │   │   ├── entities/            ← جدول‌های دیتابیس (Inventory/Customer/Invoice/...)
│       │   │   └── dao/                 ← عملیات خواندن/نوشتن هر جدول
│       │   └── ui/
│       │       ├── engine/              ← صفحه‌ی تست موتور محاسبه
│       │       ├── database/            ← صفحه‌ی تست دیتابیس (۱۰٬۰۰۰ فاکتور)
│       │       └── theme/               ← رنگ‌ها (Color.kt)، تم (Theme.kt)، فونت (Type.kt)
│       └── res/
│           ├── values/                  ← رنگ آیکون، متن‌ها، تم پایه
│           ├── drawable/                ← لوگوی سه‌فلش (ic_launcher_foreground)
│           ├── mipmap-*/                ← آیکون اپ برای نسخه‌های مختلف اندروید
│           └── xml/                     ← قوانین بکاپ/استخراج داده
├── .github/workflows/build.yml          ← ساخت خودکار APK با هر push
├── build.gradle.kts / settings.gradle.kts / gradle.properties
└── .gitignore
```

## اگر روی کامپیوتر خودتان با Android Studio باز کنید

فقط پوشه‌ی `RasticPack` را در Android Studio باز کنید («Open» → انتخاب این پوشه).
گرادل به‌صورت خودکار (`gradlew` را خودش می‌سازد چون Android Studio از قبل Gradle نصب دارد)
همه چیز را sync می‌کند و می‌توانید مستقیم روی گوشی متصل یا شبیه‌ساز اجرا کنید.
